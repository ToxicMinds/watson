Hugging Face improvement audit

Hub model cards, repository files, and official benchmark datasets checked 21 October 2026. Public scores are discovery evidence, not proof of Watson performance: most benchmarks do not reproduce two-speaker clinical calls, 32 kbit/s Opus, Slovak terminology, phone photos, Watson’s JSON schema, or its 4-CPU/8-GB Modal container.

Keep baseline

Speech · Whisper large-v3-turbo

The 809M-parameter MIT model explicitly supports English, German, and Slovak. Watson’s own test favored it over Whisper small: 2.9% vs 3.1% English WER and 26% vs 55% Slovak WER. Public ASR rankings are useful screening, but real Slovak consultations remain the release gate.

Shadow trial only

Documents · RapidOCR PP-OCRv5

Keep the small ONNX pipeline as production baseline. Trial LightOnOCR-2-1B only on a fixed corpus: its card covers German but not Slovak, requires a new Transformers/PyTorch path, and reports accelerator—not Watson CPU—performance. No public result justifies replacing RapidOCR now.

Keep, test smaller

Forms · Qwen3.5-4B Q4_K_M

Keep the Apache-2.0 4B baseline. Its GGUF is 2.74 GB and already uses llama.cpp schema-constrained output. Benchmark the related 2B Q4_K_M (1.28 GB) as a latency/cost challenger, but promote it only if multilingual extraction, null handling, and evidence grounding do not regress.

P0 · all models Pin every Hub download to a commit revision; record repository, revision, file size, and SHA-256 in a checked manifest. Fetch that exact revision and fail closed on hash mismatch. Current fetches resolve mutable aliases. The speech command records the resolved revision only after downloading; form and OCR downloads do not record equivalent provenance. The faster-whisper alias also resolves through a renamed Hub repository. A clean machine reproduces byte-identical artifacts; startup records the manifest identity; offline inference passes.
P0 · evaluation Create one versioned, privacy-safe EN/DE/SK regression corpus and run it on the exact 4-CPU/8-GB deployment shape before any model or quantization change. Hub leaderboards expose candidate models, but Watson’s domain, compression, language mix, schemas, and hardware decide actual quality and cost. Every run stores model revision, settings, per-language quality, wall time, real-time factor/tokens per second, and peak RSS. CI compares against an approved baseline.
P1 · speech Retain large-v3-turbo; seed the general-language suite with the original Google FLEURS EN/DE/SK test splits, then add consented real calls and a medical/Ayurvedic term set. FLEURS provides a repeatable multilingual floor—792 Slovak, 862 German, and 647 English test rows—but only in-domain calls reveal clinical terminology, overlap, accents, and Opus damage. Track normalized WER/CER, critical-term recall, hallucinated words during silence, language-detection accuracy, per-audio-minute time, and peak RSS. Report each language separately.
P1 · documents Replace the “fewer than 20 characters” scan test with text-quality checks; detect mixed image/text pages; benchmark 144 vs 200 DPI; retain line confidence and layout evidence where available. The current threshold can skip OCR on a mostly scanned PDF page that contains a small native-text or OCR overlay. Quality and confidence signals can route uncertain pages to review instead of silently feeding poor text into form filling. Measure character error rate, exact field-value recovery, blank-page rate, page latency, and peak RSS on native PDFs, scans, skew, glare, blur, handwriting, and phone photos in all three languages.
P1 · forms Build a deterministic extraction suite inspired by ExtractBench and IFStruct, but score Watson semantics rather than JSON validity alone. llama.cpp already constrains output to the schema. Remaining risk is plausible but unsupported content: wrong nulls, wrong speaker, duplicated facts, missing evidence, bad document citations, and instructions embedded in untrusted transcripts/documents. Score field exact/F1, null precision/recall, evidence entailment, citation validity, hallucination, prompt-injection resistance, EN/DE/SK parity, tokens per second, and peak RSS.
P2 · challengers Run only two bounded trials: Qwen3.5-2B Q4_K_M for form speed, and LightOnOCR-2-1B for hard document pages. Keep challengers behind offline evaluation; do not add runtime model routing yet. The 2B Qwen artifact is less than half the current GGUF size. LightOnOCR targets full-page structure, but lacks stated Slovak coverage and adds a large runtime stack. Both offer hypotheses, not validated upgrades. Promote only when the challenger meets the approved per-language quality floor, stays within 8 GB including concurrent pipeline components, and produces a material measured latency/cost benefit.

System topology and trust boundaries

Solid arrows carry application data or control calls. The green path is browser-to-browser WebRTC media. Dashed paths are setup or scheduled operations.

Component responsibilities

Static web app · Render

Practitioner and patient UI, Supabase client calls, browser WebRTC, two-track recording, uploads, and review. No application server runs with the static export.

Supabase · control plane

Authentication, RLS, workflow state, audit events, private objects, signaling, Edge Functions, schedules, Vault secrets, leases, and atomic result validation.

Clinical worker · Modal

On-demand Python worker with one container. Claims jobs using its own account, downloads only leased files, runs local models, sends heartbeats, and submits all-or-nothing results.

WhatsApp gateway · Render

Baileys linked-device bridge. Filters traffic, downloads allowed patient files, polls reminders, and stores sealed pairing state through the WhatsApp Edge Function.

Stripe + Google Calendar

Stripe hosts payment and returns signed/verified completion. Google supplies primary-calendar busy windows and receives bookings in a dedicated Watson calendar.

Owner operations

Database schedules check calendars and gateway health. Resend warns when the Modal allowance is exhausted or WhatsApp needs attention.

Consultation workflow

The database is the workflow authority. Browser and worker actions move records through guarded RPC transitions.

ML processing lanes

Lane 01

Transcription

  1. Claim oldest queued transcription with a two-minute renewable lease.
  2. Validate file format, size, SHA-256, and measured duration.
  3. Run faster-whisper large-v3-turbo once per speaker track.
  4. Merge on the shared browser clock; validate and commit transcript atomically.
  5. Auto-queue form work when a template exists.
Lane 02

Document OCR / parsing

  1. Claim oldest confirmed waiting document.
  2. Use native PDF text when a page has at least 20 characters.
  3. Otherwise render at about 144 DPI and run RapidOCR PP-OCRv5 Latin.
  4. Store up to 30 pages and 20,000 characters per page.
  5. Mark empty output unreadable; stale claims recover after ten minutes.
Lane 03

Form extraction

  1. Load current template, transcript lines, and newest readable document text.
  2. Run Qwen3.5-4B Q4_K_M through llama.cpp with a JSON schema.
  3. Require transcript/document evidence; discard citations that do not exist.
  4. Commit the whole draft and evidence set atomically.
  5. Require practitioner decisions before final approval.

State, retries, and shutdown

Primary state path

consent_pending → ready_for_audio → audio_imported → transcription_processing → transcript_ready → extraction_processing → draft_ready → under_review → approved

Failure branches

Transcription and extraction move to explicit failed states and can be retried. Stale transcription/form leases recover after two minutes; document claims recover after ten.

Attempt ownership

Every engine heartbeat and result carries job ID, attempt number, and engine identity. Cancelled, late, or superseded attempts cannot commit.

Safe drain

The worker waits through an idle window. Stop and wake share a database advisory lock; shutdown is refused when work arrives during the race.

Cost guard

On-demand database accounting allows three engine-hours per month. Modal’s budget and credit are separate caps. Exhaustion leaves work queued and alerts the owner.

Consent withdrawal

Current RPC cancels transcription, removes transcript/track records, and asks the browser to delete audio. It does not yet stop document processing; see SEC-06.

Credentials and data boundaries

Patient capability
Eight-character short code resolves to a 64-character invite token. The token gates join-page RPCs and names the public signaling topic; it has no explicit expiry.
Practitioner identity
Supabase JWT plus RLS and owner-checking RPCs. Practitioner reads are scoped to consultations they own.
Engine identity
Dedicated Auth account registered in engines. Job-scoped Storage reads, leased RPCs, no service key, no listening port.
Service secrets
Stripe, Google, cron, gateway, Modal wake, Resend, and owner contact values stay in Edge Function secrets, Modal secrets, or Supabase Vault.
Clinical content
Audio/documents live in private buckets. Extracted page text, transcript segments, and form answers live in PostgreSQL. Audit metadata excludes clinical text.
Ephemeral content
Live video is never stored. Worker transcription audio is removed with its temporary directory. Browser recording persists only after successful upload.

Open boundary failures block real-patient use

Cross-cutting acceptance contract

Booking consistencyRecheck availability in the reservation transaction; make retries idempotent.
Identity safetyNever merge or disclose a patient from unverified contact data.
Server-side admissionEnforce payment, consent, cancellation and authorization at join/signaling boundaries.
Clinic tenancyModel clinic, location, staff, service and room ownership before shared scheduling.
CommunicationsRecord purpose, locale, consent, template, delivery, retry and opt-out state.
PaymentsVerify amount, currency, reservation, refunds and provider events; keep card data with provider.
Exports and analyticsAuthorize and audit access; exclude clinical data unless separately approved.
External integrationsUse scoped credentials, replay protection, rate limits, idempotency and recovery.
Compliance claimsRequire technical evidence plus legal, organizational and vendor approval.
